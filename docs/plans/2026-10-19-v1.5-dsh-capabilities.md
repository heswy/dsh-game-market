## 2. 插件安装与更新

ASAR 内路径前缀：`dsh/node_modules/@deepseek-ai/`。

| 当前包/文件 | 本轮核对到的行为 | 对方案的约束 |
|---|---|---|
| `dsh-plugin-manager/README.zh.md` / `lib/index.js` | profile 自带的 package-manager invocation 优先；install/remove/enable 由 manager 负责，变更影响整个 profile | 复用宿主代理、权限、依赖管理；不要求全局 pnpm，不手写配置 |
| 同上，`installBundle` | 识别已安装包且存在 HMR 时可报 already-installed；无 HMR 可走覆盖安装，结果可要求重启 | 普通插件不具有可假设的原子 update API；必须探针证明支持模式 |
| 同上，`removeBundle` | 无 HMR 且仍在运行可报 stop-profile；卸载会改变选择/依赖 | 不先卸载自己，再依靠自己完成更新 |
| `dsh-client-ui-plugin-manager/lib/client.js` | 当前显式 Update 流程针对具有 installTarget 的条目，remove 后再打开安装流程；普通第三方插件说明仍要求移除再安装 | 不能把官方 on-demand Update UI 当成所有第三方插件已有的一键更新能力 |
| `dsh-plugin-manager/lib/typert.remote-client.js` | installBundle options 包含 enabled/saveExact/requestId/approvedBuilds/registry；结果可为 applied/restart-required/failed/cancelled/overridden 等 | 检查 Remote 外层结果和内部 application/error，不只看 RPC 返回 |
| 同上及 `lib/index.js` | install-state/install-log、cancelInstall、waitForInstall；waitForInstall 只保留活动请求 | 响应丢失后 null 不证明成功；需持久诊断与实际版本确认 |
| `dsh-plugin-market/README.zh.md` | 可选服务，默认 indexes=[]；search 标注状态、兼容性与精确 install target | 游戏平台更新功能不能依赖用户事先启用实验市场；不得静默写全局索引源 |
| `dsh-plugin-market-index/README.zh.md` / `lib/index.js` | parseMarketIndex + marketInstallTarget，npm 或固定40位 commit 的 Git source；不验证索引宣称值等于实际包 | 发布工具必须核对实际 package/version/build，不能只通过 JSON schema 就推广 |

本轮未发现通用第三方 `pluginManager.updateBundle()`。DSH 官方 on-demand 条目更新与本项目普通第三方 Bundle 更新必须区分。确需增加宿主 seam 时单独设计/审查，不在指南中伪造 API。

## 3. 原生问答与敏感审批

| 当前包/文件 | 核对结果 |
|---|---|
| `dsh-user-questions/README.zh.md` / `lib/index.js` | ask 与 askTimed；open 通过仍在等待的原请求回答；continued 通过 answer RPC steer user-question-reply；不会伪造已结束工具结果 |
| 同上 | attachWait 具有原生 deadline/claim 语义；关闭面板不发空回答，不能当取消问题；同一 continued 调用重复排队会报 REPLY_QUEUED |
| `dsh-client-ui-user-questions/lib/client.js` | QuestionCards 将 open request 与 Session projection 按 callId 关联；open attach 原生 waterfall channel，continued 绑定 RPC；native UI 已处理多窗口/草稿/超时等 |
| `dsh-client-ui-session/lib/client.js` | `uiSession.sessionStatus` 的 getSnapshot/subscribe 按 Session 提供 pendingInteraction；adapter 包含 bindingSource/renderArea；registerPendingInteraction 的 domain teardown 会 delegate 未完成 owner request |
| `dsh-user-approval/README.zh.md` / `lib/index.js` | 权限审批独立 waterfall、一次性决定、审计，never 先拒绝；普通回答 UI 无权改其 policy |

QuestionCards 等编译内部类不是本项目可依赖的公开接口。即使看到了实现，也必须用 M0 确认可公开消费的原生领域 face/slot；无稳定接口时明确提出最小 DSH seam。不能注册另一个 waterfall listener 并赌执行顺序，造成原生 UI 不再收到请求。

## 4. Logo 与现有 Runtime

`dsh-client-ui-brand-official/lib/client.js` 的 `OfficialBrandMark` 使用 `@deepseek-ai/dsh-client-ui-primitives` 的 `FishLogo`；品牌包通过 sidebar slot 填充侧栏。这里只复用标志，不覆盖宿主品牌 slot，也不把整个品牌包当普通图标依赖。

`dsh-brand` 为 branded types 库，并不提供品牌图形。能否使用 Client 公共模块与本地后备资产的许可须在 M0 固定；不能从网页热链 Logo。

项目自己的 `packages/runtime/src/controller.js` 明确保持 `sandbox="allow-scripts"`；多资源支持需新建实例资源准入而非加 allow-same-origin。现有 `packages/host/src/entry.js` 的一次性 entry 不能直接当所有子资源的长期凭证。
