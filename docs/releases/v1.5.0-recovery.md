# V1.5 候选版本使用与恢复

V1.5 尚未正式发布。使用发行候选前核对验收矩阵、固定 Git SHA 和 DSH 版本；不要将开发分支名称作为不可变安装目标。生产 stable 索引仍由发布流程最后推广。

## 更新

在市场更新提示中确认目标版本；平台先协调活跃游戏保存，再由 DSH 插件管理器安装精确 Git commit。以 Host 与 Client 两端实际身份确认更新结果；下载完成不等于当前运行版本已切换。显示待重启时，先保存并正常退出 DSH，再重新打开核对版本与 Continue。不要先卸载插件，也不要手动覆盖安装目录。

网络失败时恢复网络后重试；磁盘空间或权限失败时先修复问题，再使用市场的重试/健康检查入口。保存失败应保持暂停，确认保存成功后再更新。状态不明确时记录目标 commit、界面错误及脱敏日志；不要反复并发启动安装。

## 受控进度迁移

1. 源环境先暂停并退出游戏，确认保存成功。在“我的游戏”的游戏菜单选择“导出游戏进度”，保存 JSON。
2. 目标环境安装同一游戏且存档 schema 一致的版本。退出该游戏，选择“导入游戏进度”，读取 JSON 并核对版本/schema；存在旧进度时必须明确确认覆盖。
3. 导入校验通过后，在游戏自身的 Continue 入口恢复；迁移不复制 DSH 会话。若界面提示进度已变化，重新读取文件并核对目标后再确认。
4. 覆盖前的目标存档保留为一份备份，可用“导出导入前备份”保存成 JSON。要恢复它，按同样的导入流程操作；后续成功覆盖可能替换该备份，先另存需要保留的文件。

只迁移单游戏进度，不复制整个 DSH profile、账号、凭据或其他设置。文件含游戏进度，请由用户自行选择传递方式；不提供云同步。SHA-256 只检查损坏，不能证明文件来源可靠。游戏标识、schema 不匹配或文件超额会被拒绝；不要手改校验和绕过检查。

实际桌面独立环境间导入与重开已验证；两台实体机器间实测与正式候选安装仍以 M5 矩阵的当前记录为准。同一个 profile 不支持多个独立 Host 同时运行。
